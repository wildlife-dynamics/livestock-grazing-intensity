Technical Guide

How livestock-grazing-intensity calculates its metrics, the steps it runs, the packages they come from, and how to recompile and test it.

How the metrics are calculated

build_grazing_metrics builds the table every widget reads, one row per grazing period.

  1. Grazing periods. Each movement event starts a period in the blocks in its TO list. The period ends when the next movement event in the same zone starts. Times are cut to the day. Repeated moves to the same blocks on the same day count as one move, and the last one is kept.
  2. Area. The sum of the area_ha of the period's blocks. Block names are matched to feature names ignoring case and spaces. If any block has no match, the area is left blank and the run logs Blocks with no matching feature name: […].
  3. Cattle. Counts are added together per zone per day. Each period takes the zone's most recent count on or before its date in. Every count taken during the period adds a row from that day on.
  4. Previous grazing end. The latest date out of any earlier period that used any of the same blocks.
ColumnFormula
Grazing duration (days)date out − date in
Recovery daysdate in − previous grazing end date
Stocking density (cattle/ha)cattle ÷ area
Stock intensity (cattle-days/ha)cattle × duration ÷ area
Grazing intensity (cattle-days/ha)cattle × duration ÷ area (the same value as stock intensity; both are kept on purpose)
Grazing to Rest ratioduration ÷ recovery days, blank when recovery is 0 or unknown
Effective grazing intensity (cattle/ha over graze+rest cycle)cattle × duration ÷ (area × (duration + recovery days))

The other columns are Grazing Zone, Grazing block, Area of grazing block(s) (ha), Date in, Date out, Cattle count, Cattle count date and Previous grazing end date.

Recompiling

spec.yaml is the source. wt-compiler generates ecoscope-workflows-livestock-grazing-intensity-workflow/ from it.

./dev/recompile.sh --update   # keeps the lock file and bumps VERSION.yaml
./dev/recompile.sh --install  # a new lock file, and the packages installed

Testing

Each case in test-cases.yaml runs the workflow with its settings:

pixi run --manifest-path pixi.toml -e default bash dev/pytest-cli.sh livestock_grazing_intensity --all
