Troubleshooting

Common issues while configuring, running or changing livestock-grazing-intensity, and how to resolve them.

Configuration & connections

A data source connection fails or times out

Check the server URL and credentials in the connection, and that you can sign in to the same server in a browser with them. The account needs API access to the data the workflow asks for.

The run returns no data

The event types and feature type names in the settings must match the data source exactly, including capitals. Widen the time range if it's short.

Rename Cattle Count Columns fails: a column is not found

The cattle count event type needs communityzone and count fields in its event details. Check the event type selected under Cattle Count Events, and the field names in its EarthRanger schema.

Blank or unexpected values

Area, stocking density and intensity are blank for some blocks

A block in the movement events has no feature with the same name. Capitals and spaces are ignored, but other spelling differences aren't. The run log lists them as Blocks with no matching feature name: […]. Rename the feature or fix the block name, or add the missing feature type under Grazing Block Features.

Recovery days and the grazing to rest ratio are blank

The block wasn't grazed earlier in the time range, so there's no previous grazing to measure from. Move Since earlier to include it.

The latest period in a zone has no date out or duration

That's expected: the herd hasn't moved on yet, so the period is still open. It gets a date out once the next movement event is recorded.

A period has no cattle count

The zone has no cattle count on or before the period's date in within the time range. Move Since earlier, or check that the count events use the same communityzone values as the movement events.

The Livestock Count map is empty or missing zones

The map joins each row's Grazing Zone to a feature with exactly the same name, including capitals and spaces. Add a polygon feature for each zone, named like its communityzone value, to a feature type selected under Grazing Block Features.

Movement events have empty block lists

Only fields named from, *_from, to, to_block or *_to are read as blocks. Fields named any other way are ignored.

Developing

Recompiling fails with “Lock-file version 7 is newer than supported”

Your pixi is older than the lock format the compiler writes. Run pixi self-update and recompile.

CI says the generated files differ from the committed ones

Recompile with ./dev/recompile.sh --update and commit the changes in ecoscope-workflows-livestock-grazing-intensity-workflow/.

CI says VERSION.yaml must be greater than main's

Every change needs a new version. --update bumps it: the minor number when the run form is unchanged, the major number when it changed.

A test case fails in CI but works locally

The CI reads each data source's credentials from the repository's GitHub secrets, named in .github/workflows/test.yml. Add the missing ones under Settings → Secrets and variables → Actions.
